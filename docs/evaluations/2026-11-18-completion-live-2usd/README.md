# PR #22 live reasoning evaluation — 18 November 2026

**Recommendation: do not merge or deploy PR #22 in its current form.** Real AI independently identified a missing part and repaired it. However, the completion gate rejected geometrically correct work, retried checks that geometry changes could not satisfy, and failed to finish another review. The architecture has useful mechanisms, but this version would block ordinary valid modeling requests.

**Estimated token cost: US$0.887290 of the authorized US$2 ceiling.** No deployment, merge, modeling-code changes, prompt tuning, model switching, or additional paid retries occurred. The budget was not exhausted. The live run used 22 requests; the per-turn call safeguards stopped the first two attempted tasks, and the last task's review failed to complete. The dependent modification test was unrun.

## Verification and correction: what worked and what did not

**Confirmed with real reasoning:** the independent reader did not simply endorse the modeler's success claim. It derived seven from the user's request despite seeing only six candidate IDs. The host identified the missing object, and the modeler repaired it using that feedback. This demonstrates the basic independent-check → autonomous-repair connection without changing the prompt or adding a case-specific solution.

**Confirmed release blocker:** a check that cannot be expressed is treated as a geometric failure. The executor is told to repair the model, but the cached requirement remains `unavailable` regardless of its actions. In both the ring and stand, externally correct geometry was repeatedly rejected. This is a verification-capability/recovery problem, not inability to build these particular objects. Marking unsupported requirements as automatically passed would conceal the problem and is not recommended.

**Additional free checks against the actual AI criteria:** missing parts, wrong heights and unauthorized neighboring-object changes produced specific failing checks. The stand's misplaced shelf also failed its spatial check. The ring's misplaced peg had only the same permanent circular-layout failure; that is not evidence that its checker can distinguish correct from incorrect positions.

Geometrically equivalent meshes were also rejected because their stored recipe was `mesh` rather than `cylinder`. Equivalent local-axis transformations of the stand additionally failed width/depth checks even though the world geometry was unchanged. Those facts appear as separate failed checks in [analysis.json](evidence/analysis.json). Geometry was measured by the external oracle before classifying these as valid alternatives. Production checks were not removed or rewritten. Since permanently unavailable checks already blocked both scenes, an aggregate rejection alone must not be misreported as successful detection of every negative control.

**Preservation and state:** original projects remained unchanged on all failed turns; the ring repair retained the six surviving identities. A new unrelated modeling request executed after the failed ring history, so execution was not generally poisoned by that prior failure. Successful end-to-end completion after failure remains unproven because the plate review did not finish. No accepted live transaction reached commit, so successful live Undo/Redo and follow-up stand editing remain **unverified**, regardless of prior offline tests.

## Recommended next changes, before reconsidering release

1. **Separate incorrect geometry from unavailable verification.** Return typed, actionable outcomes. Repair actual geometric failures; resolve verification limitations through a bounded independent verification path or an explicit unresolved outcome, instead of telling the modeler to repeatedly alter already-correct geometry. Preserve independent judgment and transaction safety; do not silently pass unknown requirements.
2. **Match verification capabilities to ordinary scene operations.** General spatial-set checks, grouping/identity/editability evidence and representation-independent geometric measurements need usable interfaces. The reader should know which checks are supported and use them correctly. For example, group-reference resolution already exists, but this run's reader did not use it to substantiate membership. This is broader than adding a special circular-array command or an example prompt.
3. **Make independent review reliably bounded.** The simple slot request exhausted a 6,000-token reviewer response. Inspect incomplete-response reasons and keep the criteria exchange compact, with cost-bounded recovery. Do not simply increase the token allowance or retries. Preserve the raw completion status/finish reason in evaluation telemetry; this run saved usage and the incomplete-review error but not the full failed provider response.

After those changes, use new held-out dimensions and tasks to re-evaluate: acceptance of correct geometry, rejection of specific defects, one successful autonomous repair, a committed edit preserving identities and Undo, and a successful new request after failure. These are suggested future acceptance criteria, not authorization for implementation, another paid run, merge or deployment.
