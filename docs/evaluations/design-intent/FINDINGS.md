# What ATELIER retains, and the next focused improvement

The existing application can preserve the model, recent conversation and explicit design notes through a project reload. The more consequential gap is **the distinction between a saved decision and authoritative context the AI and verifier can use later**. Notes are optional model-authored text with source labels, and the verifier cannot cite a note as an independent source once its user quotation leaves the short history window.

This is an existing limitation shared with production, not a new regression introduced by `711a8cf`. The production and frozen candidate have the same 20-message history projection, project design-note representation and recent-history citation boundary. The candidate adds better request-start geometric inspection and independent expected-value calculations; neither is long-term intent memory.

## Offline evidence

The [eight-turn workflow](WORKFLOW.md) starts from an empty project. It creates a table, separate supports, a display panel and plinth; adds a stool; changes the plinth and table width; moves the unrelated side objects; reloads; deepens the table while preserving cable access; explicitly revises the access gap; reloads and deepens the table again.

**All eight scripted turns committed through the real browser**, ending with 12 independently editable solids, eight atomic Undo entries and 16 saved conversation messages. The eight actual-solid oracles passed. The 30 cm gap survived the first contextual edit, the explicit revision changed it to 15 cm, and the final edit preserved 15 cm. Every original component identity survived; the side objects remained unchanged during the contextual edits and revision. Appropriate rear supports and the separate panel assembly followed the table's growing back edge.

At both major reload boundaries, the harness deleted only its isolated browser's local session/conversation checkpoints and reloaded from IndexedDB. It recovered the complete project, conversation, notes and context. Turns 6, 7 and 8 also passed Undo, reload while undone, and Redo. Undo of the revision restored the older project note with the older geometry; Redo restored the newer note and geometry. The conversation remained unchanged as an audit transcript.

Both deliberate wrong variants were **blocked by measured geometry errors**, not merely unverified checks. Leaving the panel behind produced an invalid access gap; preserving the obsolete 30 cm gap after revision failed the explicit 15 cm requirement. Neither wrong proposal changed the saved model, notes or history, including after reload.

These are **scripted executor and reviewer responses** exercising the actual engine, application transactions and storage. The harness explicitly wrote the user decision and assumption notes using the existing operation. It did not demonstrate that fresh AI independently chooses to capture, recall, revise or verify them. Inspector probes were called by the harness and are labeled as such. No fresh API calls were made.

### Confirmed context boundary

Using the actual saved history before turn 6, a separate offline probe appended synthetic diagnostic messages. At 34 saved messages, the original reason still existed in the transcript and saved project note, but it disappeared from the 20-message input sent to both AI roles. The scene note remained visible to both roles.

The probe then used the real independent-review parser with an explicitly mocked SDK and the **same correct proposal and criterion**, varying only the input history. The criterion citing the original user decision was accepted with the quotation in history. With that quotation outside the window, it raised `ModelPlanError`; the host kept the result **unverified and unable to commit**. The presentation currently reports generic invalid arguments; source inspection locates the failed recent-history citation check. This is not a fresh-model failure or proof that every possible criterion selection would fail. A check preserving the measurable current gap can succeed, but does not independently establish the user's original reason or priority.

The same probe confirms that a `source:user` note can be authored without a validated user quotation, and that differently named note topics can retain conflicting values. Those isolated diagnostics were never installed in the browser project. They establish a metadata limitation, not a claim that a real model fabricated a user instruction.

Evidence: [browser replay](offline-1/result.json), [context probes](context-probes.json), [offline scripts](../../../scripts/design-intent-evaluation). An authoring mistake in the calibration criterion (`editable.minimum`) and two probe-authoring errors were corrected before final validation; all were test preparation, with no paid calls or application changes. The successful browser session was not rewritten or retried.

## Smallest reusable improvement to consider

Extend the **existing project design notes** into cited, revisable decisions. Keep the current engine, scene inspector and verifier. Avoid a second memory service, a new global planning brief or an automatic dependency solver.

1. **Attach evidence to important user decisions.** Reuse `design_note`, with a stable decision ID, a reference to the original user turn and an exact bounded quotation/reason. The host validates the quotation against the actual user message before giving it user authority. Keep model assumptions explicitly labeled and uncited. Legacy notes without evidence remain legacy context, not retroactively certified user instructions. This should use the existing agent turn, not an extra summarization call for every request.
2. **Give both AI roles the same relevant active decisions.** Carry the compact, validated evidence separately from the rolling transcript. Let independent criteria cite a decision ID and its verified quote/units, rather than inventing a current-history citation. Expected numbers must still come from user evidence or pre-edit solids, never from the candidate. Keep existing mathematical validation, scope protections and unsupported/incorrect distinctions.
3. **Make revisions explicit and atomic.** A new explicit user instruction can supersede an earlier decision. Save the replacement with the geometry in the same project transaction, so failed edits cannot install a new decision and Undo/Redo restore matching design versions. Historical conversation remains evidence, not a competing set of permanent obligations. A topic rename must not silently create two active requirements.

Object bindings proposed by the agent should remain identifiable as interpreted associations, checked against current IDs and the requested scope. Scene-observed proximity, gaps or host relationships must not automatically become lasting user constraints. Notes guide reasoning when relevant; they do not move objects by themselves or grant permission to alter unrelated work. Ask only when an unresolved decision would materially affect the result.

This transfers directly to a machine guard's service clearance, furniture access, a route through an exhibition, or the intended separation between sculptural parts: preserve an explicit reason and measurable intent, inspect the current geometry, then allow a new user decision to replace it. No object-family-specific workflow is needed.

**Not implemented.** First validate the current agent's behavior on the proposed session with separate fresh-API authorization. If the cited-decision change is then approved, keep it on its own branch and freeze it before defining fresh held-out objects and purposes. The current eight-turn rehearsal cannot establish long-project recall or fresh reasoning reliability.
