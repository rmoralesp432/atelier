# Frozen workshop reliability trials

Implementation `16361bb` is frozen. The three tasks here were defined afterward, and only evaluation code changes during preparation. Stable baseline is `f925e4c`. These compare the stable release with the integrated inspection/calculation/reliability branch, not an isolated one-line ablation. Original frozen implementations remain untouched.

Fresh GPT-6.1-sol executor and independent-reader responses run through each version's real browser, normal conversation, actual geometry engine and atomic transaction finalization. Separate browser sessions/projects and servers isolate versions. The same user prompts go to both. Follow-ups do not reveal original dimensions or tell the agent which tools to call.

Tasks: 31-part six-bay shelving (widen connected pieces, then selectively move one shelf per bay); 34-part conveyor (widen rollers/rails/supports while retaining their relationships, then raise the bed with fixed feet); 33-part screened canopy (lower the roof while maintaining support/screen connections, then rotate the assembly). Full prompts are in `scripts/reliability-evaluation/specs.ts`.

Independent acceptance uses occupied Manifold solids, bounds and symmetric differences against separate analytical construction and pre-edit transforms, not labels or the app's completion verdict. Maximum linear discrepancy is 2 mm; a 2% occupied-volume discrepancy allowance covers curved tessellation differences, with positions and dimensions separately constrained by the solid comparison. The same oracle must accept calibrated correct geometry and block displaced parts, replaced identities and unrelated-object changes before paid execution. Exact data equality protects unrelated objects and assembly parts that should remain unchanged. Labels are not used to assign expected component roles.

Report separately: explicit starting-scene inspection (including returned members), inferred connected edits supported by measured result, independent reviewer calculations and their sources, actual commit, exact identities, preserved objects, persistence/reload and Undo/Redo. Inspection is observable tool evidence, not a claim about hidden reasoning. A model can use the initial scene context without calling inspect_scene. Retained failed and incomplete attempts remain in the denominator. If creation fails, no end-to-end edit success is claimed; any later validated-fixture edit is a separate diagnostic.

At most 32 paid calls and 15 minutes per turn; two concurrent browser lanes in one ledger coordinator. No forced completion or geometry changes to pass the tests. Every call reserves a conservative amount before send; missing usage retains its reservation. All prior campaign records remain in the same ledger. Prices are the already-authorized estimates ($2/M input, $10/M output; higher reservation rates plus margin), not a confirmed bill. No auto-recharge changes. Stop on credit/access rejection, unreconcilable usage, exhausted conservative prepaid guard, or diminishing useful evidence.

Publish results and costs after each turn and each batch. Review held geometry and screenshots before interpreting success. Repeats measure variability; unfamiliar transfers test broader applicability. No application source changes during scoring, no merge, no deployment.
